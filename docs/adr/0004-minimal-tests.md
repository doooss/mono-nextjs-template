# ADR-0004 — 테스트는 버그를 잡을 수 있을 때만 쓴다

- **Status**: Accepted
- **Date**: 2026-11-21
- **Refs**: 261121_001_monorepo-bootstrap
- **Supersedes**: —

## Context

템플릿 점검에서 기존 테스트 다수가 "200 + `data` 있음" 같은 형식만 확인해, 실제 버그(path 변수를 `@Query` 로 읽음 · SQLite JSON path 오류 · 캐시 HIT 미발생)가 있어도 전부 통과했다. 테스트 수는 많았지만 회귀를 막지 못했고, 템플릿을 복제할 때마다 그 유지 비용이 따라간다.

## Decision

버그를 잡을 수 있는 테스트만 둔다. Jest = 분기 있는 로직 (Button 의 기본 `type="button"`), 화면 확인 = `pnpm spec:shots` 스크린샷. DB mock(`Repository` 를 `jest.fn` 으로 대체), 프레임워크 · 라이브러리 동작 재확인, 샘플 코드 확인은 쓰지 않고 있으면 지운다. 적대적 리뷰는 테스트 개수를 finding 으로 삼지 않는다. 규칙 → `.claude/rules/testing.md`.

## Alternatives

| 대안                                   | 기각 이유                                                                                     |
| -------------------------------------- | --------------------------------------------------------------------------------------------- |
| 분기마다 unit 1개 이상 / 커버리지 목표 | 개수가 목표가 되어 형식 단언이 늘어난다 — 이번에 버그를 놓친 원인                             |
| DB 는 mock 으로 unit 테스트            | mock 이 mock 값을 돌려주는지만 검증. 쿼리 · 관계 · DB 방언(SQLite JSON path) 오류를 못 잡는다 |
| 패키지별 테스트 실행기 추가            | 공유 패키지 동작은 앱 e2e 가 실제 경로로 검증한다 — 실행기 · 설정만 늘어난다                  |

## Consequences

- **긍정**: 삭제 — heading 존재 확인, disabled 클릭 · `tailwind-merge` · 클래스명 단언 (6 → 1). 남긴 Button 테스트는 기본 `type` 을 지우면 실패한다.
- **부정 / 비용**: 남은 테스트가 적어 리뷰어가 경로를 직접 따라가야 한다 (적대적 리뷰가 이 역할).
- **후속**: 버그 수정 · 리뷰에서 수용한 finding 은 재현 테스트부터.
